# いい感じに割り勘

**気まずい割り勘を、いい感じに。**

上司は多め、遅刻・途中参加・お酒を飲まない人は少なめ。
飲み会の会計で面倒な「傾斜つき割り勘」を、スマホで30秒で決められるWebアプリです。

**入力は「金額」と「各レベルが何人か」だけ。** 参加者を1人ずつ並べる必要はありません。

サービスは2つのモードで構成しています。

| モード | URL | 想定シーン |
| --- | --- | --- |
| サクッと割り勘 | `/` | 名簿を用意していない突発的な飲み会。その場で10秒 |
| 幹事モード | `/organizer/` | 歓送迎会・忘年会など、事前に参加者が決まっている飲み会 |

- 合計金額は **必ず** お会計金額とぴったり一致します
- 100円単位などに丸めても一致します
- 入力内容は端末の中だけで計算し、サーバーには送信しません

---

## コンセプト

飲み会の最後、幹事が「会計42,800円。部長は多め、新卒は少なめ、1人遅刻、1人は飲んでない……」
という状況でその場で開き、説明を読まずに使えることを最優先にしています。

優先順位は以下の通りで、機能追加でUIが複雑になる場合は機能を削ります。

1. 直感的に使える
2. スマホで使いやすい
3. 結果が分かりやすい
4. 合計が必ず会計金額と一致する
5. 入力が面倒でない
6. プライバシー
7. 保守しやすいコード
8. 見た目
9. 機能数

## 画面の作り

メイン画面は上から **お会計金額 → 各段階の人数 → 金額の単位 → 固定金額（折りたたみ）→ 計算ボタン**。
一般的なスマートフォンではスクロールなしでボタンまで届く高さに収めています。

```
[＋] 少なめ        [−] 0 人 [＋]
[＋] ちょい少なめ  [−] 0 人 [＋]
[＋] ふつう        [−] 4 人 [＋]
[＋] ちょい多め    [−] 0 人 [＋]
[＋] 多め          [−] 0 人 [＋]
```

左端の小さい「＋」を押すと、その段階だけの設定が開きます。

- **割合スライダー**（0.1〜3.0倍）。既定値に戻すリンク付き
- **メモ欄**（例:「田中、佐藤」）。計算には影響せず、コピーする文章に添えられます

右側の大きい「−／＋」は人数の増減です。役割が違うので大きさと枠線で区別しています。

### 固定金額

「この人は3,000円」と決めたい人だけを、計算ボタンのすぐ上の折りたたみに入れます。
人数カウンターとは独立していて、ここに並ぶのは固定金額の人だけです。
最初から1行あり、「＋」で増やせます。**金額が空の行は計算に入りません。**

### 結果の見せ方

人数で入力するアプリなので、結果も段階ごとにまとめて表示します。

```
少なめ            3,800円 / 3,700円
2人・山田、伊藤
ふつう                7,500円ずつ
2人・鈴木、高橋
ちょい多め            9,000円
1人・佐藤
多め                 11,300円
1人・部長
────────────────────────
合計                 42,800円  ✓ 合計ぴったりです
```

- 2人以上で金額が同じ行には「ずつ」を付け、1人あたりの金額だと分かるようにしています
- 丸めの都合で同じ段階の中に金額差が出た場合は、金額ごとに分けて表示します
- メモを入れた段階には、人数のあとにメモが並びます

「結果をコピー」ではLINEにそのまま貼れる文章を作ります。

```
🍻 今日のお会計
合計：42,800円

少なめ 2人：3,800円が1人、3,700円が1人（山田、伊藤）
ふつう 2人：7,500円ずつ（鈴木、高橋）
ちょい多め 1人：9,000円（佐藤）
多め 1人：11,300円（部長）

合計：42,800円

こちらの金額でよろしくお願いします！
```

末尾のひとことは既定でオン、チェックボックスで外せます。

## 幹事モード（/organizer/）

事前に参加者が分かっている飲み会向けのページです。
トップページの「サクッと割り勘」は複雑にせず、こちらを別ページとして分けています。

### 使う流れ

1. 飲み会名を入れて「新しい飲み会を作る」
2. 参加者の名前を追加し、5段階の負担レベルを設定（Excelからの読み込みも可）
3. 当日、会計金額を入力すると一人ひとりの徴収額が自動計算される
4. 集金できた人からチェックを入れると、未回収額がその場で分かる

入力は変更のたびに自動で保存されるので、ブラウザを閉じても続きから再開できます。
複数の飲み会を保存でき、「複製」で同じメンバーの次の飲み会をすぐ作れます。

### 固定額（参加者ごと）

参加者ごとに徴収方法を選べます。

| 徴収方法 | 使う設定 |
| --- | --- |
| 5段階（既定） | 負担レベル（少なめ〜多め） |
| 固定額 | 金額を直接入力 |

```
会計総額 － 出席している固定額の人の合計 ＝ 5段階の人で分ける残額
```

- **固定額は丸めません。** 6,550円と入れたら6,550円のままで、
  差し引いた残額だけに丸め単位を適用します
- **固定額0円は有効な値です**（主賓・招待者など）。**空欄（未入力）とは区別**します
- 出席者に「固定額を選んだのに金額が空」の人が1人でもいる間は、
  **飲み会全体の計算を止めて入力を促します。**
  勝手に5段階へ回すと、画面の表示と計算結果の意味が食い違うためです
  （欠席者は計算対象外なので、空のままでも計算は止まりません）
- 固定額の人は5段階の重み計算に入りません
- 欠席なら固定額も計算から外れ、参加に戻せば再び含まれます
- 固定額の合計が会計金額を超える場合や、残額を配る5段階の人がいない場合は
  **計算せずにエラーを表示**します（誰かにマイナスを割り当てたりしません）
- 徴収方法を切り替えても、負担レベルと入力済みの固定額は消しません。
  5段階へ戻すと元のレベルが復元されます

### 名前検索

名簿が増えても人を探せるよう、絞り込みの下に検索欄があります。

- 名前だけを対象にした部分一致（メモは対象外）
- `NFKC` で全角・半角、大文字・小文字の違いを吸収（`ＴＡＮＡＫＡ` ⇔ `tanaka`）
- 名前の中の空白は無視（`田中 部長` を `田中部長` で探せる）
- ひらがな⇔カタカナ変換や読みの推測はしません
- 絞り込み（要対応 / 精算完了 / 欠席）とはAND条件
- **表示上の絞り込みだけで、計算・集計・Excel出力・保存には一切影響しません**
- 検索文字列は保存しません（開き直すと空欄に戻ります）

### 計算は既存ロジックを共有している

幹事モードは独自の計算を持ちません。`src/organizer/lib/calculation.ts` が
アダプターとして次の変換をするだけで、計算そのものは `calculateSplit()` に任せています。

```
参加者一覧（欠席者を除く）
  ↓ 固定額の人を分離し、5段階の人だけ負担レベルごとの人数へ集約
calculateSplit()   ← トップページとまったく同じ関数（固定額も引数で渡す）
  ↓ 結果を参加者ごとの徴収額へ戻す
名簿に表示
```

`calculateSplit()` は元から `fixed` 引数で固定額を受け取れるので、
**固定額のために新しい計算エンジンは作っていません。**
差し引き・超過判定・丸めの対象外扱いはすべて既存エンジンの仕様のままです。

`calculateSplit()` は負担レベルの並び順（`LEVEL_ORDER`）に沿って1人ずつ結果を返すため、
レベルごとに先頭から突き合わせれば「誰がいくら」を取り違えずに復元できます。

そのため丸め処理・差額調整・**合計が会計金額と必ず一致する**という性質は、
トップページとまったく同じものが幹事モードにもそのまま効きます。
100円単位などに丸めた結果、同じ負担レベルでも1人だけ100円多くなることがありますが、
これは合計を一致させるために避けられないもので、その人には「端数 +100円」と表示します。

負担レベルの割合（0.5 / 0.8 / 1 / 1.2 / 1.5倍）も飲み会ごとに変更できます。
初期状態では折りたたんであります。

### 画面での置き場所

Excelの操作は、使う場面で分けて配置しています。

| 操作 | 場所 | 理由 |
| --- | --- | --- |
| 名簿テンプレートをダウンロード | 編集画面の上部カード | 名簿を作る入口 |
| Excelから名簿を読み込む | 編集画面の上部カード | 名簿を作る入口 |
| 集金表をExcelで出力 | 下部の「まとめて操作」 | 名簿作成・集金のあとに使う |

上部のカードは「大人数ならExcelで一括登録できます」という見出しで、
**参加者を1人ずつ手入力し始める前に**目に入る位置（飲み会名のすぐ下）に置いています。
20〜50人規模の幹事が「全員手入力するのか」と思って離脱するのを防ぐためです。
同時に「少人数なら、このまま下から1人ずつ追加できます」と添えて、
Excelを用意しないと使えないという誤解も避けています。

なお、日本語はブラウザが文字単位で改行できるため、
放っておくと「名簿テンプレートをダウン / ロード」のように語の途中で割れます。
`ButtonLabel` で意味のまとまりを `white-space: nowrap` の塊にし、
その間だけ `<wbr>` で改行を許しています。
幅が足りれば1行、足りなければ「名簿テンプレートを / ダウンロード」と
意図した位置だけで2行になります。

### Excelの入出力

- **名簿テンプレートのダウンロード**：「名簿」シート（名前・徴収方法・負担レベル・固定額・
  出欠・メモ）と「入力ルール」シートを含む .xlsx
- **旧形式（名前・負担レベル・出欠・メモ）も今までどおり読めます。**
  「徴収方法」列が無いファイルは全員5段階として扱います
- **名簿の読み込み**：空行は無視し、使えない負担レベルや出欠は**行番号つきでエラー表示**。
  件数とエラーを確認してから「置き換える／追加する」を選べます
- **集金表の出力**：「集金表」シートと「概要」シートを含む .xlsx。
  徴収方法・負担レベル・固定額・徴収予定額・回収済み金額・差額・精算状態を出力します

**Excelライブラリは追加していません。** 依存を `react` / `react-dom` だけに保つ方針を
優先し、`src/organizer/lib/xlsx/` に必要な範囲だけを実装しています。

| ファイル | 役割 |
| --- | --- |
| `inflate.ts` | DEFLATE（RFC 1951）の展開。ブラウザのAPIに依存しない |
| `zip.ts` | ZIPの組み立て（無圧縮）と展開 |
| `sheet.ts` | シートXMLの生成と解析 |

### Excel互換性で気をつけている点

読み込みは、実際のExcelが書き出すファイルに合わせて次を扱えるようにしています。

- **書式だけ設定された空セル**（`<c r="C1" s="1"/>`）があっても行が途中で切れない。
  正規表現で `<row ...>...(/>|</row>)` と書くと自己終了タグの `/>` で行が切れるため、
  開始タグと終了タグを順に走査する方式にしています
- **ふりがな（`<rPh>`）を名前に混ぜない。**
  日本語版Excelは漢字をIMEで入力すると読みを一緒に保存するため、
  素直に `<t>` を全部つなぐと「田中部長タナカブチョウ」になってしまいます
- **空行が省略されていても行番号がずれない。** Excelは中身が空の行を書き出さないので、
  `<row r="5">` の位置に置き直してからエラー行番号を出しています
- 無圧縮(store)とdeflateの両方のZIP、`sharedStrings.xml` と inline string の両方
- 名前空間の接頭辞（`<x:row>`）、Excelが付ける余分なメタデータ、複数シート
- 数式セルは計算済みの値（`<v>`）だけを読み、**数式・マクロ・外部リンクは一切実行しません**
- 見出しは「名前／氏名／参加者」「負担レベル／レベル／負担」のような言い換えも受け付け、
  列の順番が入れ替わっていても見出しの文字で判断します
- `.xls` `.xlsm` `.csv` `.numbers` は拡張子の時点で見分けて、変換方法を案内します

書き出しは Content Types・relationships・workbook・worksheet・styles をそろえた
正しいOPC構造で、金額は数値セル、文字は inline string（UTF-8）で書いています。
見出し行は太字＋ウィンドウ枠固定にしてあります。

### なぜブラウザのAPIを使わないか

`DecompressionStream('deflate-raw')` は Safari 16.4 未満や古いAndroid WebViewで使えず、
「iPhoneだけExcelを読み込めない」という事故になります。
.xlsx は数十KB程度なので、自前で展開しても速度は問題になりません。
結果として、**特別なブラウザ機能を必要とせずに動きます。**

### 集金額の扱い（回収したあとで会計が変わったとき）

徴収額は保存せず、そのつど計算し直しています。
そのため会計金額や負担レベルを変えると徴収予定額も変わりますが、
**すでに受け取った金額は変わりません。**

そこで参加者に `collectedAmount`（回収済みにした時点の徴収予定額）を持たせ、
あとから書き換えないようにしています。これがないと
「6,000円しか受け取っていないのに6,500円回収済み」と誤って集計されます。

```
徴収予定：6,500円
回収済み：6,000円   ⚠️ あと500円    [差額 500円 も回収した]
```

- 差額がないときは今までどおり「□ 未回収 → ✅ 回収済み」だけの表示です
- 差額が出たときだけ、受け取った額と不足・過剰、精算ボタンが出ます
- 回収済みの人を欠席に変えた場合は、受け取った分が過剰回収として残ります
- 徴収額が決まっていない（会計金額が未入力）ときは、チェックできません

### 人数の数え方（サマリーと絞り込みを同じ基準にする）

人数は「回収済みにチェックしたか」ではなく、**精算状況**で数えます。
チェックしただけで数えると、会計を変えたあとに差額が出ている人まで
完了扱いになり、名簿の絞り込みと食い違ってしまうためです。

| 状態 | 意味 | サマリー |
| --- | --- | --- |
| `settled` | 精算完了（受け取った額＝徴収予定額） | 精算完了 |
| `unpaid` | 未回収 | 要対応 |
| `short` | 差額あり・追加回収が必要 | 要対応 |
| `over` | 差額あり・返金等の調整が必要 | 要対応 |
| `unknown` | 要確認（金額の記録なし） | 要対応 |
| `none` | 欠席 | 対象外 |

- **`settled + unpaid + short + over + unknown === 参加人数`** が必ず成り立ちます
- 画面は「精算完了 2 / 4人　要対応 2人」のように出ます
- 名簿の絞り込みも同じ基準（全員 / 要対応 / 精算完了 / 欠席）で、
  判定は `matchesParticipantFilter()` に一本化しています
- 回収したあとで欠席にした人は出席者の内訳に混ぜず、
  `absentCollectedCount` として別に警告します

金額は「徴収予定総額 / 実際の回収済み金額 / 残り回収必要額 / 過剰回収額」を
それぞれ区別して出します。金額の集計には欠席者が受け取った分も含めます
（受け取ってしまったお金は実在するため）。

### 名簿データの扱い

- 保存先は端末の localStorage だけ（キー：`ii-kanji-warikan.organizer.v3`）
- 古い形式は自動で移行します。v3 が無ければ v2 → v1 の順に探し、
  読み込んだあと v3 として保存し直します（古いキーは消しません）
  - v1 → 回収金額の記録が無いため、**推測せず「記録なし」**として扱い画面で確定を促します
  - v2 → 徴収方法が無いため `chargeMode = 'weighted'` / `fixedAmount = null` を補います。
    **`collectedAmount` などの回収情報はそのまま保持**します
- サーバーへは一切送信しません
- 参加者名を URL や `document.title` に入れません。イベントIDもURLに出しません
- **幹事モードには広告を表示していません。** 参加者の実名を端末内で扱うためです
- 保存データが壊れていてもアプリは落ちず、読める範囲を安全な値に直して復元します

## 割り勘計算ロジック

### 負担レベルと割合

ユーザーには5段階の日本語と「0.8倍」という表示しか見せませんが、
内部では **「ふつう = 100」を基準とした整数**で持っています（小数を使うと合計がずれるため）。

| 表示 | 既定の割合 | 内部の重み |
| --- | --- | --- |
| 少なめ | 0.5倍 | 50 |
| ちょい少なめ | 0.8倍 | 80 |
| ふつう | 1倍（基準） | 100 |
| ちょい多め | 1.2倍 | 120 |
| 多め | 1.5倍 | 150 |

**この割合はスライダーでユーザーが変更できます。**（0.1倍〜3.0倍、0.05刻み）
「ふつう」だけは基準なので固定です。金額は段階どうしの相対値だけで決まるため、
ほかの4段階を動かせばあらゆる配分を作れます。

### 計算順序

1. 会計総額を整数に正規化する（未入力・0円・負数・NaNはエラーとして扱う）
2. 固定金額の人を確定する（金額が空の行は「設定していない」とみなして無視）
3. 会計総額から固定金額の合計を引く（超過ならエラー）
4. 残額を各段階の割合に応じて分配する
5. 丸める
6. 丸めの差額を調整する
7. 合計が会計総額と一致することを保証する

### 丸めのアルゴリズム（最重要）

「先に分けてから丸める」と合計がずれます。そこで **先に丸め単位で刻んでから配ります。**

1. 残額を丸め単位の**かたまり**に分ける
   例）残額32,800円・100円単位 → 328個のかたまり + 端数0円
2. かたまりを割合に応じて配る（**最大剰余法**）
   - まず `かたまり数 × 割合 ÷ 割合合計` の整数部を配る
   - 余ったかたまりは「取りこぼしが大きい人 → 割合が大きい人 → 先に並んでいる人」の順に1個ずつ配る
   - この結果、同じ段階でも1人だけ1単位多く払うことがあります。合計を一致させるために
     避けられないので、結果画面では「3,400円が1人、3,300円が2人」と分けて表示します
   - この時点で全員の金額は必ず丸め単位の倍数になります
3. 丸め単位で割り切れない端数（例：100円単位で42,850円のときの50円）は
   **いちばん負担が重い人**がまとめて引き受けます
   - 全員に1円ずつ散らすより、人間の感覚として自然なため
   - 結果画面に「端数 +50円」と表示し、なぜ半端なのかが分かるようにしています
   - **固定金額の人は端数調整の対象外**です（本人が決めた金額を勝手に変えないため）
4. 最後に合計を検算し、万一ずれていたら重み参加者の先頭で吸収します（保険）

同じ入力なら常に同じ結果になります（乱数や実行順に依存しません）。

### エラーの扱い

計算ロジックはエラーコードだけを返し、日本語の文言は `constants/messages.ts` が持ちます。
技術的なメッセージは画面に出しません。

| 状況 | 画面に出る文言 |
| --- | --- |
| 会計金額が未入力・0円 | お会計金額を入れてください。 |
| 人数も固定金額も0 | 人数を1人以上にしてください。 |
| 固定金額の合計が超過 | 固定金額の合計が、お会計金額を◯◯円超えています。 |
| 残額があるのに人数が0人 | 残り◯◯円を払う人がいません。人数を1人以上にしてください。 |
| 丸め単位が大きすぎる | 金額の単位が大きすぎて、うまく分けられませんでした。単位を小さくしてください。（警告・計算は成立） |

そのほか、全角数字・カンマ・「円」などが混ざった入力、非常に大きい/小さい金額、
同じ名前、名前未入力、割合の異常値、入力途中の状態でもクラッシュしません。

## プライバシー設計

- 会計金額・名前・負担レベル・メモ・集金状況は**すべてブラウザ内で処理**します
- 本サイト運営者のサーバーへの送信、外部API、独自のバックエンドは**ありません**
- 例外は「共有」ボタンだけで、これはOSの共有機能に本文を渡すユーザー操作です（画面にも明記）
- アクセス解析には Cloudflare Web Analytics、広告には忍者AdMax を使っています。
  詳細は `/privacy/` に記載しています

### モードごとの保存方針

| モード | 保存 | 理由 |
| --- | --- | --- |
| サクッと割り勘（`/`） | **保存しない** | その場限りの利用。前回の内容が残ると混乱・気まずさの原因になる |
| 幹事モード（`/organizer/`） | **localStorage に保存** | 事前準備 → 当日 → 集金と日をまたぐため、消えると使い物にならない |

幹事モードは保存が前提の機能なので、端末内の localStorage にだけ保存します。
サーバーやクラウドには送らないため、アカウント登録も不要です。
保存キーは `ii-kanji-warikan.organizer.v1` で、バージョンを含めているので
将来データ構造を変えても移行できます。

なお localStorage はブラウザのデータ削除やプライベートモードの終了で消えるため、
大事な集金表は「集金表をExcelで出力」で手元に保存することを画面上でも案内しています。

### セキュリティ

- `dangerouslySetInnerHTML` は使用していません。ユーザー入力はすべてテキストとして描画します
- APIキー・秘密情報は扱いません
- `public/_headers` で `X-Content-Type-Options` / `X-Frame-Options` / `Referrer-Policy` / `Permissions-Policy` を設定しています
- CSPは意図的に未設定です。ビルド構成や将来の広告タグと衝突しやすいため、
  公開後に実際の配信内容を見てから追加してください

## Cloudflare Pages へのデプロイ

1. GitHubにリポジトリを作成し、push する
2. Cloudflare Dashboard → Workers & Pages → Create → Pages → Connect to Git
3. ビルド設定

   | 項目 | 値 |
   | --- | --- |
   | Framework preset | Vite |
   | Build command | `npm run build` |
   | Build output directory | `dist` |
   | Root directory | （リポジトリ直下ならそのまま） |
   | Node version | 環境変数 `NODE_VERSION` に `20` を設定 |

4. Save and Deploy

SPAルーティングは使っていないため `_redirects` は不要です。
将来ページを増やす場合は、ルーターではなく **Viteのマルチページ構成（`/how-to/index.html` など）** を推奨します。
各ページが独立したHTMLになるため、SEOでもパフォーマンスでも有利です。

独自ドメインは Pages の Custom domains から設定し、その後 `index.html` の
`<link rel="canonical">` と OGP を実ドメインに更新してください。

  QR決済案内、URL共有、幹事の立替管理、クラウド同期

### 見送った機能：段階そのものの追加

「少なめ〜多め以外の段階も設定から追加したい」という案は、V1では見送りました。

- メイン画面の5行はすでに縦幅の大半を使っていて、行が増えると
  「計算ボタンまでスクロールなし」という一番大事な性質が崩れる
- 割合スライダーを入れたことで、段階を増やさなくても
  「少なめ＝0.3倍」のように好きな配分を作れる

将来入れるなら、段階の追加ではなく **保存できる条件プリセット**（「うちの部署の飲み会」など）
のほうが、画面を増やさずに同じ目的を達成できると考えています。

### 広告について

トップページに忍者AdMax（`src/components/AdMaxAd.tsx`）を掲載しています。
方針は次のとおりです。

- 掲載位置は**結果の下・フッターの直前**（`App.tsx` の該当箇所にコメントあり）
- 計算ボタン・結果の操作ボタンの近くには置かない（誤タップ防止）
- 枠の高さを `.adSlot` で固定してCLSを抑える
- 広告ありきでレイアウトを変えない
- **幹事モード（`/organizer/`）には広告を入れない。** 参加者の実名を端末内で扱うため
- `public/ads.txt` は広告配信事業者が指定する内容をそのまま置いています
